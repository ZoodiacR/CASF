# 🎨 CASF — Design System (Professional Visual Language)

> The source of truth for the **visual look** of the apps generated by the materializer.
> Distilled from the professional reference templates: **Linear, Vercel, Stripe, shadcn/ui**.
> The goal: a generated app should **not look "AI-made"**, but like a real product.

> 🇪🇸 [Lee esta documentación en español](DESIGN_SYSTEM.md)

---

## 0. Guiding principle

> **"Typography is what most distinguishes a professional design from a generic one."**

A design looks professional not because of the number of gradients, but because of: careful typography, a consistent spacing scale, a single saturated accent, and **professional SVG iconography** (not emojis). Less is more.

**Golden rules (2026):**
1. **Typography first.** Inter (or Geist) with weights 400/500/600/700/800. JetBrains Mono for figures/code.
2. **A single saturated accent.** Electric blue / indigo / lime / burnt orange. NEVER a rainbow of pastels.
3. **Surgical gradient.** Only in the hero and the primary CTA. Not as general decoration.
4. **Professional SVG icons** (stroke, Lucide/Feather style). **Emojis are forbidden** as iconography.
5. **Near-black surfaces** with an elevation "ladder" (each elevated layer is a bit lighter).
6. **Spacing in multiples of 4px.** 8/12/16/24 internal; 64/96 between sections. **Never 32.**
7. **Contrast 4.5:1** in both themes (verified, not "because it looks dark").
8. **`prefers-reduced-motion` + `focus-visible` + `forced-colors`** always.

## 1. Color tokens (dark by default)

Linear's "surface ladder" strategy: near-black background, each elevated surface one step lighter.

| Token | Value | Usage |
|---|---|---|
| `--bg` | `#0a0b0c` | Page background (near-black) |
| `--bg2` | `#101114` | Input / row-hover surface |
| `--card` | `#131417` | Cards / sections |
| `--card2` | `#1a1c20` | Elevated surfaces inside cards |
| `--border` | `#26282e` | Subtle borders |
| `--text` | `#e8eaed` | Primary text (off-white, not pure white) |
| `--muted` | `#9aa0a6` | Secondary text |
| `--accent` | `#5E6AD2` (Linear) / `#533AFD` (Stripe) / `#0070f3` (Vercel) | Single accent |
| `--ok` | `#2ecc71` / `#0f9d58` | Success |
| `--warn` | `#f59e0b` | Warning |
| `--err` | `#e5484d` | Error |

**Rules:**
- The accent is **one single accent** per app, derived from the product category (e.g. fintech→Stripe indigo, dev-tool→Linear blue, generic→Vercel blue).
- Accent gradient: `linear-gradient(135deg, var(--accent), <lighter accent>)` **only** in the hero and CTA.
- Accents must **not be pastel colors** nor multiple at once.

## 2. Typography

| Role | Family | Weight | Notes |
|---|---|---|---|
| Display / headings | Inter | 700–800 | negative `letter-spacing` scaled: `-0.04em` in hero, `-0.02em` in h2 |
| Body | Inter | 400–500 | `line-height: 1.55` |
| Labels / eyebrows | Inter | 600 | uppercase, `letter-spacing: 0.04em`, size 11–12px |
| Figures / money / code | JetBrains Mono | 400–500 | `font-variant-numeric: tabular-nums` to align columns |

**Display scale (progressive negative tracking):**
- Hero: `clamp(2rem, 5vw, 3rem)`, weight 800, `letter-spacing: -0.03em`
- Section H2: `1.25rem`, weight 700, `letter-spacing: -0.02em`
- Body: `15–16px`, never below 14px.

> Reference: Linear uses Inter (Display/Text) + mono; Vercel uses Geist + Geist Mono. Inter is the closest free substitute for both.

---

## 3. Spacing and radius

- **4px base.** Internal: 8 / 12 / 16 / 24. Sections: 64 / 96. **32px forbidden** (ruins both ends of the scale).
- **Radii:** 8-step scale — 4px (inputs), 8px (buttons), 12px (cards), 16px (modals), `999px` (pills/badges).
- **Shadows:** minimal. `0 1px 2px rgba(0,0,0,.4)` for cards; only the primary CTA and modals carry a deep shadow.

---

## 4. Professional iconography (SVG, Lucide style)

**Using emojis as icons is forbidden.** Every icon is **inline SVG**, 24×24 viewBox, 1.5–2px stroke, `stroke="currentColor"`, `fill="none"`, `stroke-linecap="round"` / `stroke-linejoin="round"`.

### Base catalog (`icon(name)` helper)
Each icon lives in a runtime map and is injected with `<span class="ic">`:

| Key | Usage |
|---|---|
| `shop` | e-commerce / catalog |
| `cart` | cart |
| `package` | orders |
| `utensils` | restaurant / menu |
| `table` | tables |
| `receipt` | orders / bills |
| `calendar` | schedule / appointments |
| `users` | patients / customers |
| `stethoscope` | doctors / health |
| `scissors` | barbershop / services |
| `gift` | rewards |
| `chart` | dashboard / KPIs |
| `qr` | check-in / QR |
| `camera` | scan |
| `bot` | assistant / chat |
| `user` | profile / person |
| `plus` | add |
| `trash` | delete |
| `search` | search |
| `download` | export |
| `star` | rating |

### Icon template (e.g. `cart`)
```html
<svg viewBox="0 0 24 24" width="18" height="18" fill="none"
     stroke="currentColor" stroke-width="1.8" stroke-linecap="round" stroke-linejoin="round">
  <circle cx="9" cy="21" r="1"/><circle cx="20" cy="21" r="1"/>
  <path d="M1 1h4l2.68 13.39a2 2 0 0 0 2 1.61h9.72a2 2 0 0 0 2-1.61L23 6H6"/>
</svg>
```

### Usage rule
- In a section `<h2>`, the icon goes **inside a `<span class="ic">`** with `margin-right: 8px` and `var(--accent)` color.
- In buttons, the icon goes inline with `margin-right: 6px`.
- Never more than one icon per heading; never icons + emoji mixed.

## 5. Canonical components

| Component | Professional characteristics |
|---|---|
| **Navbar** | sticky, `backdrop-filter: blur`, subtle border-bottom, brand in gradient-text |
| **Hero** | surgical gradient + large display typography + pill CTA |
| **Card** | surface ladder + subtle border + hover `translateY(-2px)` |
| **Primary button** | accent gradient, pill radius, shadow on hover |
| **Ghost button** | transparent + border, muted text |
| **Badge** | pill, background at 15% opacity of the color, full-color text |
| **CRUD table** | 11px uppercase th + `tabular-nums` on figures, row hover |
| **KPI card** | value at `font-size: 1.8rem` weight 800 + muted 12px label |
| **Input** | `--bg2`, 1px border, focus ring `0 0 0 3px rgba(accent,.18)` |
| **Toast** | fixed at bottom, 4px semantic left border, fadein animation |

## 6. Anti-patterns (what makes it look AI-made)

**FORBIDDEN:**
- ❌ Emojis as icons (🛒 📦 👥) → use SVG.
- ❌ Gradient across the whole page background.
- ❌ Multiple pastel accent colors at once.
- ❌ Default system typography without hierarchy.
- ❌ Cards without border or elevation (everything flat).
- ❌ Inconsistent spacing (random 32px, 20px).
- ❌ Centered text in data sections.
- ❌ Excessive shadows everywhere.

---

## 7. How the materializer applies this

1. **`CSS`** (constant in `materializer.ts`) uses these exact tokens and the spacing scale.
2. **`RUNTIME`** exposes `icon(name)` and replaces every emoji with SVG.
3. **`frontend_architect.md`** requires this design system in every generated UI review.
4. The **`spec_quality_reviewer`** verifies the spec asks for "professional iconography + design system" (rubric dimension 10).

## 8. View-based navigation (not "single-page scroll") ⭐

> **Pending correction (2026-09-23).** Today a generated app is **a single page** with all functions stacked (dashboard, clients, appointments, points, rewards, owner, bot…). It works, but it **looks like a demo**, not a product.

A professional app separates each function into a **view** and navigates between them with an **app shell** (like CASF Studio, which uses tabs). The goal: the user sees **one function at a time**, with clear navigation.

### Rules (when implemented)

1. **App shell with navigation:** a sidebar (or top tabs on mobile) with items: `Dashboard`, `Clients`, `Appointments`, `Points`, `Rewards`, `Services`, `Owner`, `Help`. One highlighted active item.
2. **One function per view:** each view renders **only its domain** (e.g. the "Appointments" view doesn't show the points ledger). No infinite scroll mixing everything.
3. **Hash routing (framework-free):** `#/dashboard`, `#/clients`, `#/appointments`… `hashchange` decides which view to render. Keeps compatibility with the current static preview (`/slug/frontend/index.html`).
4. **Shared state, separate views:** data lives in a single store (`store.js`/API), but **each view** is an independent, testable `render*()` (points toward the Stage 1.2 goal: split the monolithic `app.js` into per-view modules).
5. **Responsive:** on mobile the sidebar collapses to tabs/`<select>`; targets ≥ 44px (Stage 2.5).
6. **Language and theme toggles** live in the shell (persistent), not inside each view.

### Done criteria
- [ ] Navigate between all views without reloading (hash routing).
- [ ] Each view shows **one** function, not a wall of sections.
- [ ] `#/...` URL allows deep-linking and going back.
- [ ] The shell is identical across all views (brand, language, theme, nav).
